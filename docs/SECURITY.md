# Security

How E.I.S. Core protects the systems it runs on, the data it stores, and how to report a
vulnerability.

## The safety engine (`eis/core/safety.py`)

Every command executed by the platform passes through a single choke point — `run_command()` in
`eis/core/command_runner.py` — which consults the safety engine before anything runs:

1. **Blocked patterns** are refused outright, before any prompt: drive formatting (`format X:`),
   recursive forced deletes (`del /s /q`, `rd /s`, `erase /f`), `diskpart`, `cipher /w`,
   shadow-copy deletion, `shutdown`, `mkfs`, raw `dd`, `adb shell su`, bootloader unlock/flash
   commands and similar irreversible operations. These are not configurable.
2. **Classification** — everything else is labeled *read*, *state-changing* or *destructive*.
   State-changing and destructive actions require explicit confirmation (a dialog showing the
   exact command) unless the user has deliberately disabled confirmations in Settings.
3. **Fail closed** — unknown or unclassifiable input never bypasses the engine; the runner
   returns an error result instead of executing.

### Path guards

Cleaners and the duplicate finder validate every user-chosen root with `guard_scan_root()` and
refuse to operate inside protected locations:

- `C:\Windows` (and System32/SysWOW64)
- Program Files / Program Files (x86) / ProgramData
- the user profile folders: Documents, Desktop, Pictures, AppData
- drive roots themselves

Unresolvable paths are treated as protected.

## Privilege handling

- E.I.S. Core **runs unprivileged by default** and elevates only when a specific action requires
  it (SFC, DISM, restore-point creation, some service operations).
- Elevation is always user-approved via the OS prompt; the app never escalates silently or in the
  background.
- The Windows Defender center is **read-only with respect to protection state** — it never
  disables real-time protection, and there is no code path that can.

## Data handling

- **All data is local.** No telemetry, crash reporting, account system or network call is made
  except by the explicit diagnostic tools you invoke (ping, DNS, connectivity, discovery, port
  tests, ADB to attached devices).
- Customer/device/job records, notes and command history live in `data/eis.db` (SQLite, WAL
  mode). Command history also mirrors to `data/logs/command_history.jsonl` when
  `logging.record_commands` is enabled.
- **Passwords generated by the tool** use `secrets` (CSPRNG) and are displayed only in the UI;
  they are never written to disk or history.
- The settings file is validated on load; a corrupt file falls back to defaults rather than
  executing anything odd.
- Database backups (`data/backups/`) contain customer data — treat the folder as confidential and
  delete old backups you no longer need.

## Network tool disclosure

Diagnostic tools make outbound connections only on user action, to user-specified targets:
ICMP echo, DNS queries, TCP connect probes on chosen ports, and passive local discovery
(ARP/netbios-style enumeration of your own LAN segment). Nothing is uploaded anywhere.

## Reporting a vulnerability

Please **do not open a public issue** for security problems.

Contact: open a GitHub security advisory (*Security → Report a vulnerability*) or email the
address listed in the repository's SECURITY contact field if present.

Include: affected version, a minimal reproduction, and impact. You will get an acknowledgment
within a week of contact. Fixes land as patch releases; credit is given unless you prefer
otherwise. Safety-engine bypasses (a blocked command that executes, a protected directory that
can be scanned/deleted) are treated as high severity.

## Scope notes

- E.I.S. Core executes commands *you* confirm. Running an attacker-supplied "repair script"
  through the manual console is user-driven execution, not a product vulnerability — but if you
  find a way to make the engine execute a blocked pattern **without** confirmation, that *is* in
  scope.
- Python/Windows/Tkinter platform vulnerabilities are out of scope for this project; report them
  upstream.
